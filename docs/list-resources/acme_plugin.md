# pbs_acme_plugin (List Resource)

Lists the ACME challenge plugins of a Proxmox Backup Server, for `terraform query`, to import them as `pbs_acme_plugin` resources: the DNS plugins and the built-in `standalone` plugin, which always exists and can only be imported.

Needs `Sys.Modify on /system/certificates`, which PBS requires even to read plugins.

A DNS plugin's settings, `data`, are sensitive: they are null in the results, and the generated configuration has `data = null # sensitive`, which the resource refuses for a DNS plugin (`Missing setting of a DNS plugin`). Fill in the settings PBS has — its web interface shows them — before running `terraform plan`: other settings plan an update, which writes them to PBS. The `standalone` plugin has no settings, and its generated configuration needs nothing.

When PBS cannot parse `/etc/proxmox-backup/acme/plugins.cfg`, as after a bad edit by hand, it refuses to list any plugin, or to read one: the list block fails with PBS's error, which names the line. Fix the file, and list again.

-> List resources need Terraform 1.14 or later; OpenTofu and older Terraform releases do not support them. Declare `list` blocks in a `.tfquery.hcl` file and run `terraform query`; `terraform query -generate-config-out=generated.tf` writes an `import` block and a `resource` block for each object, which `terraform plan` then imports. Sensitive attributes are null in the results and in the generated configuration, and write-only ones are never read, so they are null there too; the text above says which of them, if any, the generated configuration needs filled in.

## Example Usage

```terraform
# terraform query lists the ACME plugins, the built-in standalone one
# included; with -generate-config-out=generated.tf it also writes an import
# block and a pbs_acme_plugin resource for each. The settings of a DNS
# plugin are sensitive and left out: fill in data before planning.
list "pbs_acme_plugin" "all" {
  provider         = pbs
  include_resource = true
}
```
