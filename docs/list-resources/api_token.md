# pbs_api_token (List Resource)

Lists the API tokens of a Proxmox Backup Server's users, for `terraform query`, to import them as `pbs_api_token` resources: the tokens of every user, or with `userid` those of one user.

Needs `Sys.Audit on /access/users`; without it, PBS lists only the tokens of the user the provider signs in as — the token's owner, when it signs in with an API token — and lets only that user, signed in with its password, read them or list them with `userid`. An API token without the privilege lists its owner's tokens only without `userid`, which fails with a 403 otherwise, and cannot read them: with resources included, each is left out with a warning.

A token's secret, `value`, is never known: PBS shows it only when it creates the token or regenerates its secret, so it is null in the results, as after any import. Change `regenerate` in the generated configuration to have PBS generate a new secret.

-> List resources need Terraform 1.14 or later; OpenTofu and older Terraform releases do not support them. Declare `list` blocks in a `.tfquery.hcl` file and run `terraform query`; `terraform query -generate-config-out=generated.tf` writes an `import` block and a `resource` block for each object, which `terraform plan` then imports. Sensitive attributes are null in the results and in the generated configuration, and write-only ones are never read, so they are null there too; the text above says which of them, if any, the generated configuration needs filled in.

## Example Usage

```terraform
# terraform query lists the API tokens; with -generate-config-out=generated.tf
# it also writes an import block and a pbs_api_token resource for each,
# without the token's secret, which PBS never shows again.
list "pbs_api_token" "pve" {
  provider         = pbs
  include_resource = true

  config {
    userid = "pve@pbs"
  }
}
```
