# pbs_realm_ad (List Resource)

Lists the Active Directory realms of a Proxmox Backup Server, for `terraform query`, to import them as `pbs_realm_ad` resources. Realms of other types have list resources of their own; the built-in `pam` and `pbs` have none.

The bind password is write-only and never read: the generated configuration has `password_wo = null # sensitive` and `password_wo_version = null`, which plans no change, and the realm keeps the password PBS has. A realm with a `bind_dn` needs both filled in only to be created again, when a change of `realm` or `capath` replaces it: the plan fails without them then.

PBS names its realms to anyone, as its sign-in form needs them, so listing them needs no privilege. Including the resources, as `include_resource` and `-generate-config-out` do, reads each realm, which needs `Sys.Audit on /access/domains`: without it, every realm is left out with a warning.

-> List resources need Terraform 1.14 or later; OpenTofu and older Terraform releases do not support them. Declare `list` blocks in a `.tfquery.hcl` file and run `terraform query`; `terraform query -generate-config-out=generated.tf` writes an `import` block and a `resource` block for each object, which `terraform plan` then imports. Sensitive attributes are null in the results and in the generated configuration, and write-only ones are never read, so they are null there too; the text above says which of them, if any, the generated configuration needs filled in.

## Example Usage

```terraform
# terraform query lists the Active Directory realms; with
# -generate-config-out=generated.tf it also writes an import block and a
# pbs_realm_ad resource for each. The realms keep the bind passwords PBS has.
list "pbs_realm_ad" "all" {
  provider         = pbs
  include_resource = true
}
```
