# pbs_notification_matcher (List Resource)

Lists the notification matchers of a Proxmox Backup Server, for `terraform query`, to import them as `pbs_notification_matcher` resources. The built-in `default-matcher` is listed too: PBS ships it, and it cannot be created or deleted, so importing it is how to manage it with Terraform; destroying the resource resets it to its built-in settings. A matcher has no secrets, so the generated configuration of each one plans no change. The rules of a matcher that PBS 4.2.10 and later hold as an expression, as the web interface stores them, are generated as `expression = jsonencode(…)`.

Needs `Sys.Audit on /system/notifications`; without it, PBS refuses the list.

-> List resources need Terraform 1.14 or later; OpenTofu and older Terraform releases do not support them. Declare `list` blocks in a `.tfquery.hcl` file and run `terraform query`; `terraform query -generate-config-out=generated.tf` writes an `import` block and a `resource` block for each object, which `terraform plan` then imports. Sensitive attributes are null in the results and in the generated configuration, and write-only ones are never read, so they are null there too; the text above says which of them, if any, the generated configuration needs filled in.

## Example Usage

```terraform
# terraform query lists the notification matchers, the built-in
# default-matcher among them; with -generate-config-out=generated.tf it also
# writes an import block and a pbs_notification_matcher resource for each.
# The rules of a matcher that PBS 4.2.10 and later hold as an expression, as
# the web interface stores them, are written as expression = jsonencode(...).
list "pbs_notification_matcher" "all" {
  provider         = pbs
  include_resource = true
}
```
