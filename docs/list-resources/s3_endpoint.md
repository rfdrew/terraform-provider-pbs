# pbs_s3_endpoint (List Resource)

Lists the S3 endpoints of a Proxmox Backup Server, for `terraform query`, to import them as `pbs_s3_endpoint` resources. S3 endpoints exist from PBS 4.0.

~> **The generated configuration needs the access key.** PBS returns it, but it is sensitive, so the results leave it out, and `access_key` is required: the generated configuration of an endpoint has `access_key = null # sensitive`, and validating it fails with `Missing Configuration for Required Attribute` until `access_key` is filled in. The secret key is write-only and never read: the generated configuration has `secret_key_wo = null # sensitive` and `secret_key_wo_version = null`, and the endpoint keeps the secret key PBS has. PBS needs it only to create the endpoint again, when a change of `id` replaces it: the plan fails without both filled in then.

PBS lists the endpoints on which the provider's user has `Sys.Audit` on `/system/s3-endpoint/<id>`, and leaves out the others without an error.

-> List resources need Terraform 1.14 or later; OpenTofu and older Terraform releases do not support them. Declare `list` blocks in a `.tfquery.hcl` file and run `terraform query`; `terraform query -generate-config-out=generated.tf` writes an `import` block and a `resource` block for each object, which `terraform plan` then imports. Sensitive attributes are null in the results and in the generated configuration, and write-only ones are never read, so they are null there too; the text above says which of them, if any, the generated configuration needs filled in.

## Example Usage

```terraform
# terraform query lists the S3 endpoints; with -generate-config-out=generated.tf
# it also writes an import block and a pbs_s3_endpoint resource for each. Fill
# in access_key before planning: it is sensitive, so the results leave it out.
list "pbs_s3_endpoint" "all" {
  provider         = pbs
  include_resource = true
}
```
