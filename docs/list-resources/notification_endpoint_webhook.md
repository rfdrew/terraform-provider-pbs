# pbs_notification_endpoint_webhook (List Resource)

Lists the webhook notification endpoints of a Proxmox Backup Server, for `terraform query`, to import them as `pbs_notification_endpoint_webhook` resources. Endpoints of other types have list resources of their own.

PBS returns the names of a webhook's secrets but never their values, and each entry of `secret` requires `value_wo` and `value_wo_version`: the generated configuration of an endpoint with secrets has `value_wo = null # sensitive` and `value_wo_version = null` in every entry, so validating it fails with `Missing Configuration for Required Attribute` for both, in every entry, until they are set, and the first apply then sends every value. One without secrets plans no change. `send_test_on_apply` exists only in Terraform: the generated configuration sets it to `false`.

Needs `Sys.Audit on /system/notifications`; without it, PBS refuses the list.

-> List resources need Terraform 1.14 or later; OpenTofu and older Terraform releases do not support them. Declare `list` blocks in a `.tfquery.hcl` file and run `terraform query`; `terraform query -generate-config-out=generated.tf` writes an `import` block and a `resource` block for each object, which `terraform plan` then imports. Sensitive attributes are null in the results and in the generated configuration, and write-only ones are never read, so they are null there too; the text above says which of them, if any, the generated configuration needs filled in.

## Example Usage

```terraform
# terraform query lists the webhook notification endpoints; with
# -generate-config-out=generated.tf it also writes an import block and a
# pbs_notification_endpoint_webhook resource for each. Fill in value_wo and
# value_wo_version of every secret before planning: PBS returns the secrets'
# names, never their values.
list "pbs_notification_endpoint_webhook" "all" {
  provider         = pbs
  include_resource = true
}
```
