# pbs_notification_endpoint_smtp (List Resource)

Lists the SMTP notification endpoints of a Proxmox Backup Server, for `terraform query`, to import them as `pbs_notification_endpoint_smtp` resources. Endpoints of other types have list resources of their own.

The password is write-only and never read: the generated configuration has `password_wo = null # sensitive` and `password_wo_version = null`, and the endpoint keeps the password PBS has, which plans no change for an endpoint without a `username`. One with a `username` needs both set all the same, as `username` requires `password_wo`: validating its generated configuration fails with `Invalid Attribute Combination` until they are, and the first apply then sends the password. `send_test_on_apply` exists only in Terraform: the generated configuration sets it to `false`.

Needs `Sys.Audit on /system/notifications`; without it, PBS refuses the list.

-> List resources need Terraform 1.14 or later; OpenTofu and older Terraform releases do not support them. Declare `list` blocks in a `.tfquery.hcl` file and run `terraform query`; `terraform query -generate-config-out=generated.tf` writes an `import` block and a `resource` block for each object, which `terraform plan` then imports. Sensitive attributes are null in the results and in the generated configuration, and write-only ones are never read, so they are null there too; the text above says which of them, if any, the generated configuration needs filled in.

## Example Usage

```terraform
# terraform query lists the SMTP notification endpoints; with
# -generate-config-out=generated.tf it also writes an import block and a
# pbs_notification_endpoint_smtp resource for each. An endpoint with a
# username needs password_wo and password_wo_version filled in: PBS never
# returns the password.
list "pbs_notification_endpoint_smtp" "all" {
  provider         = pbs
  include_resource = true
}
```
