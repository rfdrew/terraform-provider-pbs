# pbs_acme_account (List Resource)

Lists the ACME accounts of a Proxmox Backup Server, for `terraform query`, to import them as `pbs_acme_account` resources. PBS leaves out deactivated accounts, whose files it renames to names starting with `_`, and any other account file whose name starts with `_`.

Needs `Sys.Modify on /system/certificates`, which PBS requires even to read accounts.

An account's `contact` is what the CA returned when PBS last registered or updated it. Let's Encrypt has returned no addresses since June 2025, so for its accounts `contact` is null, and the generated configuration is invalid (`Missing Configuration for Required Attribute`) until you fill in the addresses; the first apply then sends them to the CA, which Let's Encrypt accepts and ignores. `tos_url` is the URL of the terms of service agreed to at registration.

~> **Destroying an imported account deactivates it at the CA, for good**, as destroying any `pbs_acme_account` does — and removing its resource block after the import plans exactly that. To stop managing an account, remove it from the state instead.

-> List resources need Terraform 1.14 or later; OpenTofu and older Terraform releases do not support them. Declare `list` blocks in a `.tfquery.hcl` file and run `terraform query`; `terraform query -generate-config-out=generated.tf` writes an `import` block and a `resource` block for each object, which `terraform plan` then imports. Sensitive attributes are null in the results and in the generated configuration, and write-only ones are never read, so they are null there too; the text above says which of them, if any, the generated configuration needs filled in.

## Example Usage

```terraform
# terraform query lists the ACME accounts; with
# -generate-config-out=generated.tf it also writes an import block and a
# pbs_acme_account resource for each. Fill in contact where the CA keeps no
# addresses, as Let's Encrypt does not.
list "pbs_acme_account" "all" {
  provider         = pbs
  include_resource = true
}
```
